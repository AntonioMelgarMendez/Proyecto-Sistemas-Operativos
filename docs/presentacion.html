01 / El problema

Compartir un recurso
no significa usarlo sin reglas.

PRODUCTOR→[ 1 ][ 2 ][ 3 ][ · ][ · ]→CONSUMIDOR

Búfer lleno

El productor debe esperar espacio. No sobrescribir elementos pendientes.

Búfer vacío

El consumidor debe esperar datos. No extraer información inexistente.

02 / La abstracción

Un monitor reúne
estado, operaciones y reglas.

Exclusión mutua

Un mutex protege celdas, índices y contadores.

C17 no incorpora monitores: los construimos mediante encapsulación.

Espera por condición

not_full: espacio.
not_empty: datos.

La condición no almacena permisos como un semáforo.

03 / La regla fundamental

Despertar no basta.
Hay que volver a comprobar.

lock(mutex);
while (count == capacity && !closed)
    cond_wait(not_full, mutex);
// comprobar cierre, insertar y actualizar estado
cond_signal(not_empty);
unlock(mutex);

wait libera el mutex y lo recupera al retornar.
signal no entrega inmediatamente el mutex.

06 / Corrección y observación

La UI muestra el monitor.
No lo reemplaza.

Invariantes

0 ≤ count ≤ capacity
producidos − consumidos = count

FIFO; índices circulares; todos los datos bajo lock.

Snapshots + eventos

Copiar con lock; dibujar sin lock.
Sin sleeps dentro de la sección crítica.

Historial acotado: puede omitir eventos visuales a máxima velocidad.

08 / Cierre seguro

Terminar también
es parte de la sincronización.

closed = true→broadcast ambas→pthread_join→destruir recursos

Finalización normal: drenar el búfer.
Cancelación: detener y reportar CANCELLED.

No usar pthread_cancel. No destruir un mutex mientras un hilo pueda necesitarlo.
